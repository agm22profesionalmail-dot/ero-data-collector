# Despliegue — auditoría de seguridad 2026-09-27

Rama: `security/auditoria-20260927`. El frontend se despliega solo al hacer
push a `main` (workflow `deploy-cloudflare.yml`) y **depende de las RPC
nuevas**, así que el orden importa: primero base de datos y funciones, y el
merge a `main` al final.

Todo lo que sigue se hace desde una copia local del repo con esta rama.
No hay credenciales en el repo: cada paso pide las suyas.

---

## 0. Requisitos

- Supabase CLI: `npx supabase --version` (o `npm i -g supabase`).
- Acceso al proyecto Supabase (dashboard) y al repo de GitHub (settings).
- Un generador de secretos. En PowerShell:
  ```powershell
  -join ((1..48) | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) })
  ```

  o en bash: `openssl rand -hex 48`.

### 4.1 Alta del administrador (A1) — paso manual

```sql
-- localizar el uuid de la cuenta con la que el admin entra en la web
select u.id, i.provider, i.provider_id
  from auth.users u join auth.identities i on i.user_id = u.id
 where i.provider_id = '<id de Discord del admin>';

insert into public.admin_identities (user_id, label)
values ('<uuid>', 'admin')
on conflict (user_id) do nothing;
```

Sin esta fila `admin_login` devuelve `bad_credentials` aunque usuario y clave
sean correctos (y cuenta como intento fallido).

### 4.2 Comprobaciones en SQL

```sql
-- anon no puede ejecutar ninguna admin_*
select p.proname, has_function_privilege('anon', p.oid, 'execute') as anon_exec
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public' and p.proname like 'admin\_%' escape '\'
 order by 1;
-- todas false

-- ya no existe ninguna firma (text, text, ...) con p_user
select proname, pg_get_function_identity_arguments(oid)
  from pg_proc where proname like 'admin\_%' escape '\' and pg_get_function_identity_arguments(oid) like 'p_user%';
-- 0 filas

-- clave genérica fuera
select k from public.app_secrets;   -- admin_user, admin_pass, admin_pass_dummy, send_email_url

-- catálogo cargado
select kind, count(*) from public.gear_catalog group by 1;

-- Vault
select name from vault.secrets where name = 'edc_internal_secret';
```

## 8. Comprobaciones post-despliegue

Sustituir `<URL>` por la URL del proyecto Supabase y `<ANON>` por la anon key
de `js/config.js`.

```sh
# Edge Functions sin secreto → 403 (o 503 si el secret no está puesto: revisar 3.1)
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/json' -d '{}' <URL>/functions/v1/relay-bot-dms
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/json' -d '{"action":"check_bounces"}' <URL>/functions/v1/send-artist-credentials
# con el secreto → 200
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/json' -H "x-edc-secret: $SECRET" -d '{}' <URL>/functions/v1/relay-bot-dms

# Ko-fi sin token válido → 403
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/x-www-form-urlencoded' --data-urlencode 'data={"verification_token":"x","type":"Commission"}' <URL>/functions/v1/kofi-webhook

# admin_* con anon → 401/404 (sin permiso de EXECUTE / función no expuesta)
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "apikey: <ANON>" -H "Authorization: Bearer <ANON>" -H 'Content-Type: application/json' -d '{"p_token":"x"}' <URL>/rest/v1/rpc/admin_list
# firma antigua ya no existe → 404
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "apikey: <ANON>" -H "Authorization: Bearer <ANON>" -H 'Content-Type: application/json' -d '{"p_user":"a","p_pass":"b"}' <URL>/rest/v1/rpc/admin_list
# admin_login con anon (sin sesión) → 401/403
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "apikey: <ANON>" -H "Authorization: Bearer <ANON>" -H 'Content-Type: application/json' -d '{"p_user":"a","p_pass":"b"}' <URL>/rest/v1/rpc/admin_login

# CSP y cabeceras en la web
curl -sI https://eroplayerdata.pages.dev/ | grep -i -E 'content-security-policy|x-frame-options|x-content-type|referrer-policy|permissions-policy'
curl -s -o /dev/null -w '%{http_code}\n' https://eroplayerdata.pages.dev/vendor/supabase-js/supabase-js-2.116.0.min.js   # 200

# CORS de submit-feedback: github.io ya no se refleja
curl -s -D - -o /dev/null -X OPTIONS -H 'Origin: https://<usuario>.github.io' <URL>/functions/v1/submit-feedback | grep -i access-control-allow-origin
# → https://eroplayerdata.pages.dev
```

En el navegador:
1. `https://eroplayerdata.pages.dev/` carga sin errores de consola (ni
   `Refused to load` de la CSP) y el login con Discord/X funciona.
2. Iniciar sesión con la cuenta del admin → `?admin` → usuario y clave →
   entra; recargar la pestaña mantiene la sesión; cerrar la pestaña la pierde;
   "Salir" revoca el token. Con 5 claves erróneas seguidas → mensaje de
   bloqueo 15 min.
3. Artista aprobado → `?panel` → clave → fichas con imágenes y nombres. En las
   herramientas de red, la respuesta de `artist_group` NO trae `player_type`,
   `hair`, `gear_*`, `anim_name` ni `weapon_main`: solo `sheet`.
4. Aprobar un artista de prueba desde el panel local → llega el aviso con una
   clave temporal; el panel del artista exige cambiarla antes de mostrar nada.

## 9. Riesgo residual documentado (A3)

`artist_group` devuelve rutas de imagen con el identificador interno de cada
pieza (`Hed_XXX`, `Har_SQD001`, …) porque el panel las pinta desde el CDN
público de Flexlion. Con el RSDB público podría rehacerse a mano el mapeo a
los ids numéricos, pero ya no se entrega ningún objeto con la forma de
`PlayerConfig` ni los campos `weapon_main` / `anim_name`. Si en el futuro los
renders se sirven completos desde el servidor, la ficha puede dejar de
mostrar las imágenes por pieza.
